# Stark

- This is a standalone Uzu-derived Rust/Metal engine. Keep host application integration in separate repositories.
- Preserve upstream copyright and licenses. Record source revisions and patch provenance.
- Preserve source-bound validation results and upstream provenance. Record new validation runs separately when tooling changes.
- Mixed-precision inference is allowed. Choose activation, accumulation, recurrent-state, cache and weight precision through numerical validation and measured performance. Full F32 execution is not a production requirement. Preserve existing F32 results as reference evidence; qualify new precision paths against matching references and record their precision policies and validation separately.
- Do not log prompts, responses, token vectors, decision probabilities, credentials, or exception dumps. Keep native validation artifacts private and publish aggregate results and hashes only.
- Serialize complete decisions against a single loaded model. Cache only identical immediately consecutive token sequences with the same context size. Clear on failures and restarts; never persist the cache. The generation worker may also reuse the attention KV state, and for hybrid models a recurrent-state snapshot taken at a prefill chunk boundary, of the immediately preceding request's chunk-aligned shared token prefix when the context size, loaded model instance, host cache scope and state-affecting request options such as MTP match. Clear it on failures, cancellation, image requests and restarts; never persist or log it.
- Every new model/backend or state-affecting inference path must assess and implement generation prefix reuse where exact state restoration is possible, or document a concrete blocker. Follow `docs/MODEL_ONBOARDING.md` and qualify each artifact separately.
- Image support is the default for image-capable models. Every new family, checkpoint, quantization, format or backend must qualify cache correctness, matched text inference performance with images loaded, and supported text MTP with images loaded; image requests keep MTP off and invalidate text prefixes. Do not recover text functionality by silently choosing an image-less default or stripping a supported draft head. Record explicit N/A evidence for genuinely text-only sources or absent compatible MTP. Follow `docs/IMAGE_DEFAULT_PARITY_PLAN.md` and `docs/MODEL_ONBOARDING.md`.
- Track model-specific compatibility, correctness, precision, memory and performance attempts in `docs/model-experiments/`, following its README and template. Record failed, rejected, invalid, inconclusive, abandoned and resource-deferred attempts as well as successes; bind artifact/build identities, evidence scope and promotion decisions, and link the attempt IDs from the implementation PR. Keep correctness, measured speed, code adoption and installed-build status separate; do not transfer qualification between artifacts.
- Models, binaries, generated distributions, private evaluation data, and runtime artifacts stay ignored.
- Keep dependencies locked. Use Rust 1.98.1 for scoring builds and `uv` for Python tools.
- Write documentation in Markdown without emojis. Do not use shell heredocs.
- Use Conventional Commits, `git ai-commit codex`, and author `Codex <noreply@github.com>`.
- Push authorized work to its branch. Do not open a PR unless explicitly requested.
- Do not enable inherited upstream cloud/signing/release infrastructure. New distribution infrastructure requires a separate scoped implementation.
- Toolchains, local checks and test layout are in `CONTRIBUTING.md`; the documentation index is `docs/README.md`. Reference pages under `docs/` describe current behaviour and change with the code; dated validation records go in the pull request or under `docs/archive/runs/`, benchmarks under `docs/benchmarks/`.
