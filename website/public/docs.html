01 / SETUP

Get started.

You’ll need an Apple silicon Mac with macOS 26.4 or newer. Model size and context length determine how much memory and storage you need.

  1. Install Stark. Download the Mac app, open the DMG and follow the installation steps.
  2. Choose your work. Open Stark from the menu bar and choose Beginner → Guided setup. Select General Work for OpenWork or Coding for OpenCode Desktop, then continue.
  3. Choose your priority. Keep Quality, selected by default, or choose Speed. Select Find a model to review a recommendation for your Mac.
  4. Download and run it. Choose Download and set up, then follow the prompt to start the model.
  5. Connect your app. Follow the guide to install OpenWork or OpenCode Desktop and allow its connection. In OpenCode, open a project and select Stark and the recommended model in the model picker. You can also chat in Stark. Advanced mode gives you the full catalog and import options.

These steps describe the new guided flow in development. Installed releases may show an earlier setup.

Recommendations check compatibility, available memory and storage. Quality uses task rankings. Speed adds a minimum parent-model score and a model-weight budget that grows with your Mac’s RAM. If no model qualifies for Speed, choose Quality or browse Advanced.

Rankings use a bundled whatmodel.sh snapshot, reviewed and refreshed manually about monthly. Setup never queries that site; model discovery and downloads can still need internet access. Scores compare parent models and do not measure each quantized export’s quality. Stark checks the selected export’s memory requirements separately. For benchmark information behind the rankings, see whatmodel’s About this repo section. Recommendation policy and maintenance.

02 / CONNECTIONS

Connect your apps.

With a model running in Chat mode, open Connections → Apps in Stark and choose Connect. Select Stark and your running model in the other app’s model picker.

OpenWork

Install OpenWork and open a workspace folder it can work in. If Stark asks, quit OpenWork completely and reopen it after connecting.

OpenWork setup guide ↗

OpenCode Desktop

Install the desktop app and connect it in Stark. Approve its engine when asked; updates or restarts can require a new approval.

OpenCode setup guide ↗

Other compatible apps

Open Connections → Connect your own app and copy the Base URL, API key and Model ID into an OpenAI-compatible provider. Keep the key private. The API is local to your Mac.

IMAGES / DEVELOPMENT UPDATE

Image coverage by build.

The additional paths below are implemented and locally validated in the image-support development branch. Use a source build containing this work; installed releases can have earlier capabilities. Stark checks each image artifact before enabling input.

Qwen dense and MoE

Quantized text decoders retain a complete BF16 vision tower. The pinned dense Qwen3.8 27B and quantized Qwen3.5 35B-A3B passed image execution, cancellation and recovery checks. The small Qwen3.5 0.8B quantized reference cases match source logits exactly.

Retained Lily Flash-Next

The pinned Lily Q4-XL image artifact passed the full vision-tower comparison and image execution, cancellation and recovery checks. Its separate typed text-only conversion omits the vision tower.

Gemma 3 and Gemma 4

Gemma 3 4B BF16 has source-reference and worker/API evidence. Gemma 4 E2B and E4B have recorded execution checks. These results belong to the tested artifacts and builds.

Further full-model checks

BF16-source Qwen 35B MoE, Gemma 3 12B/27B and Gemma 4 12B/26B/31B have implemented paths or component evidence. Full-checkpoint generation is unverified. The extracted Gemma 4 31B vision tower passes its three reference cases.

Support is specific to the checkpoint, format and build. Quantized vision-tower weights, adapter-only files, audio and video are outside these image paths. Image requests clear conversation-prefix reuse and keep multi-token prediction off.
