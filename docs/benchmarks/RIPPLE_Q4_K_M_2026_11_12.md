# Ripple Q4_K_M native validation, 2026-11-12

Stark prepares and executes the standard Ripple-65B Preview Q4_K_M artifact
through its native Rust/Metal Ripple graph. Packed Q4_K/Q6_K bytes remain
unchanged. Q4_K uses the existing Safe Metal two-row block kernel only for
Ripple's six released projection geometries; a separate pipeline cache prevents
this choice from changing other graphs. Q6_K retains its established kernel.
Activations, accumulation, controls and KV state use F32. No diagnostic flags
are needed in production.

  `ricursiveAI/Ripple-65B-Preview@e27e171792f303d74c048184e8259ba663cfa0d5`.

- Locked Rust 1.98.1 release worker, with generation built separately from
  scoring. Native inference uses no Python or external inference engine.

The independent CPU oracle executes the unchanged, hash-pinned publisher
decoder using the same quantized weights dequantized to F32, one layer at a
time. Its NumPy Q4_K/Q6_K decoding was checked against pinned GGML equations
and independent scalar element indexing. Oracle versions were PyTorch 2.14.1
and Transformers 5.15.1. The eight-position reference took 176.153 seconds,
excluding file hashing. This does not qualify parity with the original BF16
checkpoint or reproduce publisher quality scores.

## Timing scope

The final production worker's two warm Q4 requests measured 5.368 and 5.464
decode tokens/s, median **5.416 tokens/s**. Warm ten-token prefill took 1.928
and 1.810 seconds, median **1.869 seconds**. Each request sampled 32 tokens;
decode rate counts the 31 tokens after the prefill token. One preceding warmup
was excluded. Context size was 512, sampling greedy, with no speculation or
profiling. These are short, unscreened, serialized requests on a working Mac.
They establish local operation and approximate speed, not sustained throughput.

A subsequent same-worker Q8 cohort, after all compilation and engine tests
finished, measured 6.206 and 5.651 tokens/s, median **5.929 tokens/s**. Its
median warm ten-token prefill was 1.622 seconds. Q4_K_M saves about 30.0 GB
of weight storage; Q8 decoded faster in these short runs. The samples are too
small and uncontrolled to establish a general throughput difference. The Q8
timing cohort used the existing prepared Q8 artifact; its payload was not
rehashed in this run. An earlier Q8 cohort that overlapped compilation is
excluded from this comparison.

An exploratory scalar-kernel timing cohort overlapped a numerical check and
is excluded. A diagnostic block-kernel cohort guided selection; all final
correctness and timing evidence above uses production defaults. Earlier Q8
reports remain source-bound and unchanged. This artifact's checks do not
supersede their numerical evidence.

The new artifact inherits Ripple's request-local cache policy. Cross-request
prefix reuse remains disabled because the graph exposes no qualified cache
snapshot/restore interface. Long-context execution, image input, structured
tools and speculative decoding are not qualified by this run.

Private fixtures, model files, executable artifacts and worker captures stay
ignored. Only aggregate results and hashes are published.

## Reproduction

Use the preparation command in [Ripple support](../RIPPLE.md), selecting
`ripple-q4-k-m`. Then run:

```sh
uv run --project tools --locked --python 3.12.13 python scripts/ripple_full_reference.py --model-path models/ripple-q4-k-m --output runtime/ripple-q4-reference
cargo +1.98.1 run --release --locked -p stark-engine --example hybrid_parity -- runtime/ripple-q4-reference 0.001
uv run --project tools/converter --locked --python 3.13.13 python scripts/validate_ripple_generation.py --model models/ripple-q4-k-m --worker target/release/stark-generate --output runtime/ripple-q4-generation.json
```
