# Dense Qwen3.8-27B oQ4e MTP on M5 Max

This study binds native dense `qwen3_5` conversion, MTP execution and prefix
reuse to one checkpoint. The development target is **70.8 useful decode
tokens/s**. The final six-response diagnostic measured **46.05 tokens/s**;
the target was **not met**. Quiet-host screening did not admit a measurement
window, so the throughput observations are unqualified. This record does not
supersede the separate Flash-Next results.

All four source shard hashes match the pinned publisher's LFS identities.
Conversion checks payload hashes against the source manifest. The publisher
comparison reuses those manifest hashes; it does not claim a second payload
rehash. Private receipts remain under ignored `runtime/` paths.

The graph has 64 target layers: 48 Gated DeltaNet and 16 full-attention layers,
plus one full-attention predictor. Native execution is Rust/Metal. The
converter retains a complete declared quantized predictor; the loaded worker
advertises zero drafts by default, recommends three and permits up to three.
The dense graph and checkpoint are separate from `qwen4_exp` Flash-Next.
Admission requires owned causal full-attention and DeltaNet target layers and
one owned causal full-attention predictor. Sliding/ring caches, KV sharing and
additional unstored convolution wrappers are outside this admitted path.

The source uses group-64 affine 4/5/6/8-bit matrices. Conversion losslessly
widens five/six-bit integers and mixed-width fused projections into existing
eight-bit storage. Every source integer and BF16 scale/bias is preserved;
this costs additional storage and memory bandwidth. Activations and attention
KV use BF16, matrix products accumulate in F32, DeltaNet recurrence and
convolution history use F32, and BF16 vocabulary readouts become F32 inputs
to the exact rejection sampler. The inert `output_gate_type: "swish"`
annotation does not change Qwen3.5's sigmoid attention-output gate.

## Numerical scope

The pinned MLX comparison environment uses MLX 0.32.4 and MLX-LM revision
`72be8c955d9a0d3099bd01865af288e0e947c3fa`. Three private code prompts,
thinking disabled and 32 greedy outputs each, matched the native zero-draft
route exactly by generated-token hash. This is a bounded continuation check;
it does not establish broad coding quality or long-context parity.

An initial batched DeltaNet closed-form solve changed one of those three
continuations. A teacher-forced audit isolated the drift after the first row,
even with every proposal forced accepted, ruling out rejection rollback as
its cause. The repair evaluates flat chains of two to four positions with
the same per-row TreeVerify/StateAdvance arithmetic as the dense zero-draft
route while sharing projection weights. On the failing case, all 32 positions
then matched all 248,320 vocabulary logits bit for bit: maximum absolute and
RMS errors were both zero. The corrected three continuations all matched MLX.
The fused ordinary full-accept update can differ numerically on a synthetic
toy model; exactness here is relative to the admitted dense verification route.

The final M5 verifier fuses the same Gram, identity solve, output and separate
StateAdvance operations for flat chains of two to four positions. Each
threadgroup keeps a 32-by-128 state tile locally; speculative verification
leaves committed state untouched. The qualified 16-key-head/48-value-head
geometry passed the same all-vocabulary checkpoint audit with zero errors.
Other layouts retain the checked fallback. This is an implementation of the
existing arithmetic, with no temporary runtime selector or Cargo feature.

Source comparison also identified oMLX's intentional post-normalization draft
variant. The target's final norm is applied to its captured residual before
the head; later draft steps consume the head's normalized output. This changes
the proposal distribution while exact rejection still uses the same target.
In the pinned MLX/oMLX head replay, the target normalization seam was bit exact.
Six synthetic head rows over priming and two chained steps had matching top-one
choices; cross-engine BF16 matmul differences remained, with logit maximum
absolute error 0.125 and relative RMS error 0.44–0.70%. This is bounded head
parity evidence, not a claim of complete cross-engine numerical identity.

Private audit sources were retained with hashes before removing temporary
examples from the product tree. The teacher-forcing harness SHA-256 is
`8224f1f23d7a53137842f8e5c5b959133da3943d2ceb8b2568e7226561211a92`.
It retains tokens and logits in memory and emits aggregate errors only.

## Prefix state

The worker captures the last complete non-final 1,024-token prefill boundary.
A retained session includes target recurrence/convolution state, BF16 normalized
target hidden state, F32 next-token logits and both attention positions. Attention prefix
rows remain in the same session. Reuse requires the same model instance,
context, scope and exact selected draft count. Error, cancellation, reset,
image operation, idle expiry and restart clear retention through the shared
worker lifecycle. Publication occurs only after a successful reply is flushed.

The exact snapshot payload formula for this configuration is:

`48 × 48 × 128 × 128 × 4 + 48 × 10240 × 3 × 4 + 5120 × 2 + 248320 × 4`

This is **157,896,704 bytes**, about 150.58 MiB, excluding control structures,
allocator overhead and temporary copies. The target's 16 attention layers and
the predictor retain 69,632 bytes of BF16 KV per token: 570,425,344 bytes
(544 MiB) for 8,192 slots, excluding scratch/suffix storage. These are payload
counts, not process RSS or a measured peak-memory claim. Attention reserves
another 1,024 suffix slots per layer: **9,216 slots and 612 MiB** across the 17
states at an 8,192-token context. The extra capacity is 68 MiB. Metal can map
sparse pages on demand; actual mapped/resident KV pages were not measured.

The private toy Metal check covers the first-token input/readout contract,
16-token greedy equality at draft depths zero through three, fresh/restored
1,100-token prompts with greedy and seeded sampling at every depth, foreign
model rejection and cancellation. The Metal DeltaNet snapshot test uses the
real supported 128-dimensional head geometry.

## Benchmark protocol

The [public reference](https://jacar.es/en/local-llm-benchmarks-apple-silicon/)
reported 70.8 tok/s using oMLX 0.7.3.dev2, Lightning MTP, temperature 0.6,
thinking disabled and six 768-token API code responses. The public run predates
the checkpoint's October 29 requantization and does not pin a checkpoint
revision. Its original prompt corpus was unavailable for this study. These
measurements are an independent target test with a separately hashed private
three-prompt corpus.

`scripts/benchmark_qwen38_dense.py` measures two responses per prompt after
warmup, context capacity 8,192, temperature 0.6, top-p 0.95, top-k 20, seed 42, thinking
disabled and three drafts. Useful decode rate is `(sampled_tokens - 1) /
decode_seconds`; the initial prefill draw is excluded. Only delivered sampled
tokens count toward throughput. Proposal, acceptance and phase counters include
completed verification work even if an output stop truncates a queued round.

The full target requires six complete 768-token responses, the sampled policy,
at least one warmup, a median at least 70.8, and passing quiet-host screening.
Short or greedy diagnostics cannot qualify the target. Screening reuses the
repository's CPU, competing-model, GPU-idle, thermal, paging and compiler checks.
Prompts, responses and token vectors are never written in reports; receipts
contain aggregate counts, timings and hashes.

## Measurements and checks

The final worker produced six complete 768-token responses after one warmup.
It ran one request at a time with prefix reuse disabled:

| Private prompt | Formatted input tokens | Repeat 1 tok/s | Repeat 2 tok/s |
| --- | ---: | ---: | ---: |
| 1 | 63 | 41.24 | 40.72 |
| 2 | 58 | 47.13 | 45.69 |
| 3 | 52 | 46.41 | 47.19 |

Input counts were derived with the same pinned tokenizer and exact template
arguments used by the benchmark; the corpus identity is hashed in the receipt.

Median: **46.05 tok/s**. The median and every response were below 70.8.
Repeated responses for each prompt had identical token hashes. Two screened
attempts timed out while waiting for a quiet window after warmup; their partial
observations are excluded from this table. The table is an unscreened
diagnostic, not a production throughput floor or a reproduction of oMLX.

An aggregate timing probe separated CPU encoding, GPU execution and host
readback. The three 128-token greedy cases spent about **50.8–52.9 ms on the
GPU per verification round**, **0.67–0.70 ms encoding**, and **0.13 ms reading
back/widening logits**. The outer verify phase also includes sampling,
submission/wait overhead and accepted-state commit. CPU graph encoding was
not the main bottleneck.

The artifact-bound prefix exactness run passed **40 comparison cases**,
including restart, and **six lifecycle actions**: five clearing actions and
tokenize/decode preservation. It used context 4,096,
first-token target 1,536, one synthetic tool, one instruction paragraph,
follow-up lengths `(1, 1, 1)` and eight generated tokens. Actual first/follow-up
lengths were 1,218/1,278/1,340/1,406. Greedy, seeded stochastic MTP, selected
depth changes, scope/context changes, errors, cancellation and final-chunk
edges matched fresh execution and expected reuse counts. Eligible follow-ups
reused 1,024 tokens. This qualifies the tested artifact and worker; it does not
transfer another artifact's evidence.

An additional timing run alternated fresh and cached worker order over two
blocks and two rounds per block, with four observations per arm and turn.
All outputs matched. With default zero-draft requests, median follow-up
prefill/first-token time changed from 1.68/1.69/1.87 seconds fresh to
0.45/0.46/0.66 seconds cached, each reusing 1,024 tokens. The cold first turn
remained about 1.48 seconds in both arms. These are unscreened latency
observations, separately recorded from the exactness result.

## Other-engine investigation and rejected experiments

The pinned oMLX driver supplied the post-normalization proposal policy described
above. It also uses native packed five/six-bit matrices, specialized mixed-width
verification kernels, a coarse draft readout with exact candidate rescoring,
and a GPU sampling/scheduling pipeline. Its custom verifier explicitly permits
BF16 rounding differences and occasional greedy divergence from stock MLX.
Those policies need their own numerical qualification. See the pinned
[driver](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/mlx_lm_mtp/batch_generator.py)
and [verification kernels](https://github.com/jundot/omlx/blob/2165e75726ba83d9651dbaced61c97728da77bba/omlx/patches/qwen35_verify_qmm.py).

A bounded private MLX diagnostic using unchanged source quantization and the
reviewed model patch measured 55.32 tok/s median over three 128-token sampled
responses. It uses GPU F32 sampling with Stark's logical filter order and omits
the full oMLX scheduler, custom QMM and coarse readout. Its output lengths,
floating-point sampling and implementation differ from the six-response Stark
run, so it establishes no matched speedup or seeded equality.

Three additional kernel experiments were rejected:

- Smaller threadgroups with unchanged reduction order gave only small W4
  changes and no useful W8 improvement.
- MLX-style eight-lane GEMV reductions preserved new scalar/batch equality but
  ran slower on most actual matrix shapes. Their numerical policy was not
  promoted.
- A private small-batch matrix-MMA prototype preserved exact integer operands
  and passed CPU F64 and scalar/batch checks. Its best W4 observations did not
  meet the predeclared 15–20% port threshold, and active W8 cases were slower.
  Its synchronized wall timer also differs from the native GPU timer.

The failed candidates, sources and receipts are retained privately. No unused
experimental kernel variants or temporary Cargo selectors remain in the
production path. The remaining storage expansion and pipeline differences are
concrete follow-up work; **70.8 tok/s remains unachieved**.
