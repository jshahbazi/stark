# Qwen3.8 residual fusion and exact CPU sampling

This study starts at `51bcada80f4f433438bae5bdd8c1dbfca38108dd` on
`codex/qwen38-inference-performance`, following the
[desktop stability](QWEN38_STABILITY_2026_10_29.md) and
[AC power controls](QWEN38_POWER_MODES_2026_10_29.md) studies.

## Research and fixed configuration

A fresh search found an [MLX single-token MoE bandwidth report](https://github.com/ml-explore/mlx/issues/4509).
Its gathered single-token route underuses bandwidth relative to larger batches;
separate per-expert matmuls are much slower. This supports investigating work
inside the gathered path. It does not establish that an MLX change transfers to
Stark. Stark already fuses expert gate/up/SwiGLU and down/combine, and earlier
row-packing and input-cache trials did not improve its measured chains.

The selected new candidate extends the down/combine epilogue to perform the
following hyperconnection write. This is a Stark patch to the existing Lily
body at pinned revision `e22d58fa7cc488493fb1b5d810a198bd29730aeb`; no new
external kernel implementation is imported. The
[upstream record](../../vendor/lily-core/UPSTREAM.md) describes its provenance.

The checkpoint remains `fabiogreter/Qwen3.8-Flash-Next-lily-q4-xl` at
`0f94842e3682b49acace4daeb4cf2e65a6f94f83`: 55 shards, 106,905,155,192 bytes.
All 55 stat identities match the preceding complete SHA-256 verification.
Quantization is unchanged. The policy remains BF16 activations, F32 reductions,
logits and GDN recurrent state, Q8 attention K/V and resident experts. MTP,
vision and speculation remain disabled. Host power preferences are unchanged.

Measurements use the same M5 Max with 40 GPU cores and 128 GB, with other
desktop applications active. Each sampled request has 4,096 input tokens,
256 outputs, context 4,352, temperature 1, top-p 0.95 and seed 42. Top-k 20
and disabled top-k are reported separately. Decode rates count 255 steps after
the prefill draw. Each request resets model state and RNG. No prompt, output,
token vector, logits or probabilities are persisted; private ignored records
contain scalar timings and hashes.

## MoE output and hyperconnection fusion

The fused kernel keeps the original Q4 dot expressions, per-expert BF16 round,
slot-ordered F32 combination and shared-expert gate. It explicitly rounds and
stores the final branch as BF16 before using that value in the original F32
hyperconnection injection expression. The row owner updates its column in
each residual stream. The graph orders both output buffers before subsequent
consumers. This removes 48 dispatches and their intermediate dependency levels
per decode token; it does not remove any experts or model computation.

The original down/combine and standalone injection remain available as
controls. The shared host admission now also rejects slot counts outside
1–16, matching the shader's fixed scratch capacity.

Exact component controls cover 36 cases with 16 sequential steps each:
production dimensions with and without the shared expert; different stream,
slot and group counts; duplicated and permuted experts; nonzero offsets and
canaries; zeros, subnormals, cancellation, large finite activations and
ordinary/saturated gates. All 5,241,600 compared branch/residual bytes match.
Reference and candidate aggregate SHA-256:
`ef24fafaac2b7746786d608b8dfeb3e7fbd7c1fe5d6d51de27b67b9af4bef947`.

A streaming component benchmark uses 48 distinct weight sets totaling
442,368,000 viewed bytes, a two-second warmup and 16 alternating AB/BA pairs.
The first window measures:

| Down/combine plus injection | Original us/layer | Fused us/layer |
| --- | ---: | ---: |
| Mean | 31.599068 | 29.845269 |
| Median | 32.004777 | 29.186633 |

The mean reduction is 5.55% for this component, about 0.084 ms across 48
layers in that window. It is not a 5.55% complete-model speedup.

All 32 full-vocabulary teacher readouts at 4K match the previously qualified
hash `04e8a4ddd7a69f156ade5d021bf474930c01ff737545ea2fdadd23c70561d7ef`.
Reset replay and invalid-ingest/step recovery checks also pass.

## Sampled generation

Separate production-worker windows each run one warmup and four measured
requests per sampling case:

| Worker | Top-k 20 median tok/s | No top-k median tok/s |
| --- | ---: | ---: |
| Starting worker | 71.4748 | 59.3653 |
| MoE injection fusion | 70.7349 | 64.4270 |

All 20 outputs match the existing seeded trajectory hashes. These windows
have substantial drift and do not isolate a per-change throughput gain.
The starting worker's nucleus rates decline from 64.52 to 55.40 tok/s within
its five requests. Different between-window directions must not be attributed
to the fusion.

A separate private worker switches the fusion between requests on one loaded
model. Its private selector leaves injection enabled in both routes, changes
only fused versus original execution, and acknowledges the selected route.
It uses one warmup per route/case followed by four ABBA blocks per case;
case order alternates between blocks. The weights, scratch, queues, sampling
implementation and precision policy remain shared. Stage profiling and host
monitoring are disabled for this control. The normal request activity guard
remains enabled on both routes.

All 36 requests match their expected hashes; 32 are measured after warmup.
Pooled rates divide 2,040 decode steps per route/case by their summed decode
time:

| Same-loaded route | Top-k 20 pooled tok/s | No top-k pooled tok/s |
| --- | ---: | ---: |
| Original down plus injection | 47.6232 | 43.5906 |
| Fused down and injection | 46.5665 | 44.1042 |
| Relative observation | -2.22% | +1.18% |

The four individual ABBA blocks also disagree:

| Block | Top-k 20 relative change | No top-k relative change |
| --- | ---: | ---: |
| 1 | -1.00% | +1.03% |
| 2 | +2.59% | -6.76% |
| 3 | -9.33% | +7.07% |
| 4 | -0.07% | +1.92% |

Original-route top-k block rates fall from 63.71 to 36.98 tok/s. This run
establishes no dependable complete-model speedup from the fusion. It retains
the component gain and exactness evidence; the 77–80 tok/s normal-desktop
target remains unmet. This control does not measure the cause of its drift.

The private response acknowledgement repeats the requested selector; inspection
verifies that the selector reaches the decode call. It is not an independent
GPU execution counter. The harness inherits its environment; a post-run check
finds no `STARK_QWEN38_PROFILE_OUTPUT` variable, but that absence was not sealed
at launch. Subsequent controls explicitly remove that variable. These limits
are preserved with this run rather than retroactively strengthening its receipt.

## Exact parallel probability mapping

Nucleus-only sampling maps the complete 248,320-element vocabulary through
independent exponentials before the serial probability sum. A worker-owned
Rayon pool now handles that mapping for candidate lists of at least 65,536
elements. It starts lazily, uses at most four available CPUs and parks between
maps. Small lists, a single available CPU and failed pool startup use the
serial path. A failed parallel output reservation also falls back to the
existing serial allocation path; this is not a process-wide OOM guarantee.
There is no global pool or retained readout/probability cache.

Each element keeps the original F32 subtraction/division followed by F64
`exp`. Only those independent elements are computed concurrently. F64 totals,
filtering, CDF traversal and RNG advancement remain serial and in the original
order. Both Rayon 1.12.0 and the test-only SHA-2 dependency were already locked;
no package versions or checksums change.

A paired control visits 256 real model readouts from the existing 4K,
temperature-1, nucleus-only trajectory. It alternates AB/BA on each readout,
compares every probability bit, checks three serial filter configurations and
matches full sampler decisions plus RNG state. All 63,569,920 probability
elements and 768 filter states match. Reference and parallel probability
SHA-256:
`bdf46ae05302f38893953e49ee09e76c58fa2ac3f9a7c3d182ed82e4c67736df`.
The streamed little-endian selected-token-byte SHA-256 is
`620391749aeed66656767a281ef9fe4c84dd210caf5299f9210b80774633917a`;
this encoding differs from the JSON token-array hashes in generation receipts.

| Paired CPU work | Serial mean / median ms | Parallel mean / median ms |
| --- | ---: | ---: |
| Probability mapping | 0.920267 / 0.921063 | 0.379962 / 0.371208 |
| Complete sampler | 2.428301 / 2.482937 | 1.869726 / 1.937729 |

The mean reductions are 58.7% for mapping and 23.0% for the complete sampler
in this control. These timings exclude model inference. Default CPU controls
also cover finite IEEE edges, lazy admission, serial fallback, filtering,
seeded draws and RNG state. Top-k 20 remains on the serial small-list path.

### Sampled generation with the parallel mapper

A new private control retains the fused MoE path in both arms and switches
only serial versus parallel probability mapping on one loaded model. It
retains the same pool through measured requests, clears inherited stage
profiling configuration, and records execution-derived parallel/serial map
counts. It runs four warmups and 32 measured requests in four ABBA blocks per
sampling case. All 36 output hashes match. Every nucleus candidate executes
256 parallel maps, every nucleus control executes 256 serial maps, and both
top-k 20 arms execute 256 serial maps. No measured request is filtered.

| Case and selected mode | Actual map | Pooled tok/s | Median tok/s | Range tok/s |
| --- | --- | ---: | ---: | ---: |
| Top-k 20, serial | Serial | 63.182 | 65.365 | 57.469–70.551 |
| Top-k 20, parallel | Serial | 56.893 | 64.593 | 38.468–67.499 |
| No top-k, serial | Serial | 57.724 | 60.845 | 41.139–67.114 |
| No top-k, parallel | Parallel | 58.454 | 61.873 | 41.317–67.021 |

Nucleus-only pooled throughput is 1.3% higher and its median 1.7% higher in
this window. Its four block mean differences are +2.297, +0.375, -0.931 and
+1.366 tok/s. The overlap and changing direction do not establish a robust
end-to-end gain. Top-k 20's selected modes have identical serial computation,
yet their pooled rates differ materially, demonstrating this run's timing
variance independently of a mapper treatment.

An independent rootless macmon v0.10.0 capture covers 214 complete adjacent
intervals, 216.103 seconds. Only intervals wholly inside each request enter
the summary; coverage is 83.2–87.0%. GPU MHz is weighted by active residency
within each request, active ratio and temperature by interval duration, then
request means are averaged within each group:

| Case and selected mode | Active MHz | GPU active ratio | GPU C |
| --- | ---: | ---: | ---: |
| Top-k 20, serial | 1017.6 | 1.000 | 84.7 |
| Top-k 20, parallel | 849.1 | 1.000 | 84.4 |
| No top-k, serial | 964.0 | 0.995 | 84.1 |
| No top-k, parallel | 943.0 | 0.998 | 84.1 |

Frequency is an active-state residency mean from IOReport GPU performance
states. These are device-wide observations and do not identify which
application owned GPU time. Their source and limitations match the preceding
[clock study](QWEN38_STABILITY_2026_10_29.md#production-sampled-replay-and-sustained-clocks).
The 77–80 sampled tok/s normal-desktop target remains unmet. The retained
changes have exact numerical controls and measured component improvements;
their complete-model observations are qualified above.
