## Method and limits

- **Sources.** The main session transcript, the transcripts of the 21 agents it dispatched (prefill, decode and 8-bit kernels, records, launch fusion twice, admission, parity tooling, scoreboard harness, verifier divergence, 8-bit feasibility, 8-bit bytes, 8-bit default, two web readings of MLX-Serve, the MLX-Serve source read and its three sub-readers, prefill attribution, benchmark formalization and its survey), the 88 saved agent reports and the coordinator's notes. The agent transcripts were used, not only the reports, so that variants tried and dropped inside a workstream are covered.
- **Check.** Each slice was read in full by a separate read-only reviewer, which listed every item (code change, kernel variant, sweep, measurement, hypothesis, tooling change, bug, dropped idea, stopped work) and searched the records for it by name, parameter and number. An item counted as recorded only when the record states its outcome and, where the source has numbers, the same numbers.
- **Verification.** Every correction to an existing record in section 1 was checked by the coordinator against the transcript or the receipt before the record was changed. Figures that the reviewers could not see because tool output was clipped were recovered from the raw transcripts and are marked "recovered".
- **Second pass.** After this record was written, four further read-only reviewers checked every item that the 18 inventories list as not recorded against this record and the corrected records. They found no wrong figure, name, date or outcome; five housekeeping items with no trace, a list of finer figures that had been summarized away and about ten imprecise sentences, all since added or reworded. A script then confirmed that every figure in this record appears in the transcripts, reports or receipts that predate the audit; the four exceptions are roundings checked by hand.
- **Limits.** Slices overlap, so the counts above include repeats. Single runs are marked; a single run on this host is an observation, not a result (the same configuration moved by up to 25 percent between runs). Items the reviewers judged recorded were not all re-read by the coordinator. Private inventories, one per slice, are in `runtime/session-audit/inventory/` (ignored).
- **Levels and artifacts** are as on the differences page: engine (`inkling_slice` diagnostic), worker (`stark-generate`), server (llmprobe through the gateway); "original" and "8-bit" are the two artifacts. Times of day are local unless marked UTC.

## 13. After the session: merge and a lint commit that the gates did not cover

Pull request 196 was opened on 2026-11-23 for the whole branch (86 commits, 72 from the earlier Codex branch and 14 from this session; 265 files, 74,571 insertions) and merged into `main` as `2bab5129` at 22:51 local. Before the merge another session added `76638e3f`, "fix(ci): clear ruff format and clippy findings on the Inkling branch": formatting of five converter files and 35 clippy fixes in the `inkling_slice` engine module and the generation worker (`is_multiple_of`, `as_chunks`, a collapsed condition, a constant assertion, a fixed-size array and three F32 literals shortened to values the commit states are bit-identical), 22 files.

CI passed on that commit. The gate set of this session (exact reference, drafting on equals off at four lengths on both artifacts, replay hashes, worker smoke, prefix validator, tool calling), the natural-text quality probe and the standard benchmark all ran on the build from `7e73e180`, one commit earlier. They have not been re-run on the merged tree. The merged code is therefore one lint commit past what was qualified; a CI pass is not model qualification. Re-running the gate set on `main` would close this.

## 14. Ideas the audit surfaced that were on no candidate list

Added to the candidates section of the differences page:

- 8-bit weights for the draft head's dense layers, and a cheaper vocabulary read, as the route to a cheaper draft command (decode workstream).
