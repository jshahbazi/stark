## Serial target

The native session runs the whole 48-visit itinerary with per-visit BF16 keys, values and convolution histories. It embeds tokens, executes the three-pass loop, evaluates the four original MXFP8 expert visits, normalizes the final residual and reads back 200,058 F32 soft-capped logits in one command and completion. NVFP4 retains BF16 activations, four-over-six quantization and F32 products and reductions. MXFP8 uses per-32 E4M3FN activation groups and source E8M0 weight scales, with the BF16 SwiGLU and expert boundaries. A model- and context-bound GPU snapshot captures the exact target state; resetting the logical length makes old cache slots inaccessible.

The source comparison supplied four consecutive teacher rows after a four-token prefix, built by the same four singleton chunk boundaries for both implementations. The initial native build agreed on all four greedy decisions and replayed all 200,058 first-row logits byte-for-byte after snapshot restore. Connected logits differed by 5.48–9.99% relative L2. Final hidden state differed by 9.62–12.02% relative L2. Exact-ingress replay of the original MXFP8 path matched all 36,864 input reconstruction words and 13 of 16 expert output rows; worst-row L2 was 0.09854% and peak normalized error was 0.15060%.

Trace of all prefix rows found the first model difference at the first token in pass-one physical layer 10 after exact BF16 MLP ingress. Router logits differed in 114 of 128 F32 words, route weights in four of eight, and the routed middle in 12 of 9,216 BF16 words. The expert output then differed in 357 of 2,304 words, with 0.09019% L2. The layer's convolution retained those differences over the next three positions. At the first three teacher rows, pass-one physical layer 11 received exact current-token query, key, value and dynamic convolution projections; earlier cache history perturbed its key and value convolution rows.

## Layer-major prompt scheduling

The eight-row serial-geometry candidate changes only iteration order. Each row has its own residual state. Each logical visit processes the eight cache updates in causal order, and uses the serial accumulation and rounding kernels. The resident weight layout and dispatch count stay fixed. Separate per-row taps allow the draft feature update to run in chronological order when a draft is active.

The M5 Max pilot alternated both launch orders in one loaded session across eight different 32-token windows from the pinned 4,096-token fixture, with one warmup per arm. Target cache and convolution bytes, final BF16 taps and next-token F32 logits all matched exactly in every pair. The median paired wall ratio was 0.9952, with eight nominal wins and ratios from 0.9908 to 0.9972. Baseline and candidate arm medians were 786.95 and 782.14 ms. This is below a practical 10% speed gain. Keep the production token-major order and reserve the layer-major diagnostic for measuring true weight sharing. DSpark and image prefill were outside this pilot.

The paired pilot binary and aggregate SHA-256 are `345f9304202f12257cdbe21be340ae80a2e703adb25180745549aa0cac4a81b2` and `175ce4456bae8ca68be105701ab27ef454c3e588f3b181b5c94719c1548fc114`. The private short and long token bundle SHA-256 are `99469e19eac3aeac29388473fba5a46de078626f217eea1f79653af9fe7ad415` and `74d6457708d31fe3ba6aeeab41b836d6ac7cd825cb3837fc3ddacc64e0c19719`. ## 20261121-INKPREFILL-02 · 64-row shared projection and grouped experts

This candidate processes up to 64 prompt rows per command with layer-major residual lanes. A BF16 attention projection kernel shares one weight read across four dot products with the serial row's FP32 grouping and BF16 round. The GPU router groups NVFP4 expert inputs across the complete tile and restores the per-token route order before summing. MXFP8 uses the existing row kernels. Every local and global cache write remains causal, including all four convolution histories. The draft uses per-token feature taps and chronological commits. Brief remainder tiles reuse the attention projections and evaluate experts in their serial geometry. This path is M5 Max-specific and initially opt-in.

Eight AB/BA pairs used 64 distinct tokens per window, one loaded original checkpoint with the vision tower resident, and a separate warmup per arm. Candidate and baseline matched all live target cache and convolution state, BF16 draft taps and each of 200,058 continuation logits in all eight pairs. Restoring the 1,024-token snapshot and replaying the following 64-token tile reproduced the continuation logits byte-for-byte across local ring wrap. The candidate won eight of eight pairs. Median paired wall ratio was **0.29391** with ratios of 0.2899–0.2997. Arm medians were 1,572.892 and 462.426 ms, equivalent to 40.69 and 138.40 input tok/s in this short test. The holdout and end-to-end worker claims are recorded separately. SHA-256 `2a656b7b39cbcb7ef88e9d23cd555868d3629e725454e43a60ec366a28e53c2c` identifies the benchmark binary and `d8c8c6cfb1c0d12e706a032fd10aec24eb03115abcd13e1939b845965b6a27ab` identifies the aggregate. [Grouped expert probe](2026-11-21-inkling-mini-grouped-nvfp4.md)

The complete 4,096-token replay ingested the pinned tokenizer's token IDs in **33.017 s**, or **124.06 input tok/s**, once the checkpoint and 64-row workspace were ready. Turning the workspace on increased Metal's tracked allocation by 45,826,048 bytes. The worker reserves 128 MiB for the optional tile alongside its separate persistent state allowance. All native logits replayed exactly after restoring the complete prefill. Compared with the pinned Ollama runtime's eight 512-row prefill chunks, native decoded logits differed by 35.21%, 23.63%, 13.18% and 4.16% relative L2 on the four teacher rows. One greedy decision agreed. Those figures measure cross-runtime prompt and decoder differences jointly and keep full-source parity unqualified. The benchmark binary and aggregate SHA-256 are `5485259b4e4d8ccf321903e30e8f23c788f926586d54ee3a6d42426c51a03c00` and `db72143934d8a9c0722b9ce916f453c733b6f0b19d7c9ec63fe20b04f99f1796`.

The median paired wall ratio was **0.31591**, from 0.31438 to 0.31730. Repeating a single tile checks timing and correctness at this context depth. It provides no additional corpus coverage.
