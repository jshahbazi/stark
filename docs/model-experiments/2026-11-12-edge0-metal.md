## Hypothesis and implementation boundary

Moving the established F32 arithmetic onto the existing Metal graph can remove
per-operation host activation transfers and CPU recurrence. Small causal prefill
groups can reuse Q8/BF16 trunk weights and selected expert weights across tokens.
The artifact retains its unchanged mixed Q8_0/Q3_K/IQ4_NL/BF16/FP8/F32/F16 bytes.
Initial activations, accumulators, recurrence and attention caches remain F32;
reduced activation/state precision requires a separate numerical candidate.

Select the candidate only with both `STARK_EDGE0_REFERENCE=1` and
`STARK_EDGE0_METAL=1`. Preserve the reference selector without Metal as the
existing execution policy. Catalogue admission remains excluded. Context stays
512, MTP stays unavailable, prefix reuse stays unsupported, and images are N/A
for this text-only source. Retain the source MTP files.

Preserve stored negative A and tiled V-head association. The latent stage applies
stored column scales once, computes each selected expert's U product separately
and reduces in routed order. Grouped-U reassociation is outside this attempt.
Metal does not supply F64 routing: a bounded readback of router scores retains
the source F64 exponential/reduction and F32 probability boundaries.

Prefill uses at most eight tokens per group. Each layer must update causal
recurrence/attention in token order, batch its independent projections, group
expert jobs by selected expert, and return each contribution to its original
token/route position. A scalar decode optimization alone cannot close Phase 4.
