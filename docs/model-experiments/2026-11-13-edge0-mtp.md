## Hypothesis and boundary

without moving the target to Lily. Reuse the existing backend-independent
`MtpSampler` and exact rejection sampler. The head is a full attention/indexer
and ordinary expert block, separate from the target's latent D/U path.

The first slice is model-free: checked draft storage and source conventions,
complete native checkpoint/rewind, and a backend-independent round/stream
controller with deterministic fake backends. Keep capabilities false and the
512-token cap. No restricted draft vocabulary, four-draft mode, speculative
batched-target promotion, catalogue or distribution changes are authorized
by this attempt.

## Source findings before executable head integration

The exact source pin remains Edge0
`b7900cbb322926ccebdcd0c0c5a1280497ecff22`. The expert record size alone does
not identify its physical layout. `tools/mtp_rt.py::blob_of` interleaves gate/up
rows and separates four planes: gate/up packed codes, down packed codes,
gate/up F16 scales, down F16 scales. This is not a contiguous GGML Q2_0 tensor
and must not be exposed as one. Source-specific checked row/block views retain
those original planes and logical row association without repacking.

The same export adds `1.0` to every F32 norm record. Runtime uses those stored
values as final gamma, with no second addition. `core/mtp.hpp` describes the
default hidden norm as one RMS over all 10,240 residual values, followed by
per-stream hidden projection. Its optional stream normalization and Lily's
grouped norm are a different arithmetic policy; Lily head qualification cannot
be inherited. A native head must fix and independently validate its norm policy.

Draft cell `i` pairs the target residual at `i` with the token at `i+1`, applies
RoPE position `i`, and predicts `i+2`. The head owns its K/V cache. Prompt pairs
initialize that cache, and rejected/speculative suffixes must be restored or
overwritten before reading. These source facts guide integration; the foundation
does not yet implement the executable head or cache catch-up.

## Implemented foundation and validation boundary

The staged storage API maps the retained dense and expert files read-only and
validates exactly 29 dense records, their complete geometry, encoding, offsets
and coverage. Expert row views preserve four physical planes, expose checked
logical gate/up/down rows and keep mapped owners alive after the parent is
dropped. Scalar Q2 inspection preserves IEEE NaN/Inf behavior; executable head
kernels must add selected-value/output finite gates. Mapping and inspection do
not establish large-payload integrity beyond the existing pinned preparation
receipt and immutable-source assumption.

The generic synchronous controller consumes the existing `MtpSampler` contract.
It checkpoints before drafting, rewinds before ordinary serial target steps,
and restores the exact committed input prefix. `finish()` acknowledges cleanup
failure; early Drop fences failures, and cancellation invalidates the request.
Cleanup does not sample. The backend must supply a complete target-and-head
checkpoint and exact replay before the controller can be used for this model.
This replay-based foundation makes no MTP speed claim.

The private native target primitive captures exact F32 recurrent/convolution,
causal attention K/V and index prefixes (including the partial index pool),
PLE history and bounded token history. Checkpoints have no Debug/serialization
implementation. A lazy loaded-model identity, reset epoch and execution-policy
key reject incompatible restoration. Restore prepares independent mutable GPU
owners before swapping; immutable control buffers may share ownership. It is
admitted only at a completed positive target boundary, not initial empty state.

At the pinned 512-token context, calculated payload is 147,136,520 bytes per
full target checkpoint and 150,231,040 bytes for replacement mutable GPU owners:
297,367,560 additional bytes combined before allocator/driver rounding, metadata
or fence scratch. The 256 MiB cap bounds retained snapshot payload, not total
memory. No current production caller invokes this private API. The future MTP
planner must admit snapshot multiplicity, replacement staging and draft-head
resources before connecting it to execution. Draft-head cache/state is absent
from the target-only primitive and must be added for complete MTP restoration.

Neither controller nor checkpoint foundation is connected to worker capability
dispatch. The model still reports MTP unavailable and prefix reuse unsupported.
No draft forward, acceptance rate or MTP on/off measurement has run.

The first combined build at `6f014a11` failed before executing tests: the empty
boxed snapshot slice needed an explicit slice type, and the GDN owner needed
the `MTLResource` trait import for its device accessor. Preserve both failed
build logs. The correction changes type/import plumbing, with no numerical
threshold or state inventory change.

At `b672bab0`, the full native suite passed: 1,078 tests, 156 ignored,
251.20 seconds, plus seven integration tests, two profile tests and three
documentation tests. Its production Clippy run rejected the intentionally
unused private checkpoint foundation and staging reexports. Those helpers
remain private, with scoped documented lint allowances until integration.

Review also found a restoration-domain counterexample: restoring a position-zero
snapshot drops graph/GDN owners that a later positive snapshot expects as
immutable restoration prototypes. The corrected `Edge0MetalSingleStepV1` policy
requires a completed target advance at position greater than zero on both
capture and restore. Native MTP begins after prompt processing and an initial
target readout; general initial-state snapshots are outside this policy. The
shared admission predicate and zero/positive-tail counterexamples make that
boundary explicit. Reset or any checkpoint failure invalidates existing handles.

### Registered actual-target checkpoint gate

After the model-free foundation, register a separate bounded check of the
composite `QwenModel` capture/restore wrapper. Use one loaded virtual-wrapper
Metal model, context 512, an ordinary 32-token prefix and four forced steps.
Capture at position 32, collect four finite complete readouts in private RAM,
restore and require exact F32 bits. Corrupt a second checkpoint to the excluded
empty boundary; require rejection, cleared graph/history/position and invalidated
old handle. Reingest the prefix after failure and require the same four readouts.

This performs 76 successful advances and 12 complete readouts, with eight paired
bit-exact comparisons. Sampling is absent. Require 64 GiB available before the
owned Cargo/test process tree, a 48 GiB aggregate RSS watchdog, a 600-second
wall deadline and exactly one selected ignored test passing. Bind source,
helper and prepared-receipt hashes before launch and recheck source afterward.
This gate covers short target-state restoration only, excluding draft-head
state, sparse-index execution beyond the current cap and MTP sampling.
