## Starting evidence

The supplied audit covered `f6dc9f3f1` (v0.24.2). It reports that two installed Qwen3 artifacts advertised 40,960 tokens and that JevK5, retained-image Lily, Qwen3.8-27B and the external MLX-Serve text artifact advertised 262,144. All six reached the expected finite limit, rejected a one-token overflow, recovered and kept the same limit in managed `/v1/models`. Prefix reuse passed on all six. The three artifacts advertising MTP passed the tested parity and reuse checks. Both installed artifacts advertising images passed a synthetic image request and text-prefix invalidation. These checks establish behavior at the lengths exercised. Full-window generation quality is a separate qualification.

The audit used a separate instrumented worker for controlled memory pressure. Reloads moved native Qwen from 580 to 40,960 tokens and hybrid MLX-Serve from 90,112 to 262,144. Inkling’s earlier 570,368 → 528,384 result used different startup budgets. The PR record also identifies a rejected Qwen probe that unnecessarily cut 40,960 to 27,648. Both are useful controls when diagnosing a future shrink. [Matched workers and rejected probe](model-experiments/2026-11-25-shared-generation-context-sizing.md)

## 1. Make Lily’s reuse prediction accurate

`tail_tokens` describes how a request selects its own capture boundary. Restoring a previous snapshot has an additional condition. On the pinned retained-vision Lily artifact, a 2,048-token midpoint needs **17 suffix tokens** for an exact restore. On a full 4,096-token boundary, **two suffice**. A shorter midpoint suffix causes a cold prefill and the request succeeds. The engine already tests 16, 17 and the full-boundary case. The worker’s readiness and the qualification script cannot currently express that distinction. [Worker contract](../crates/stark-generate/src/generation.rs) · [Engine boundary cases](../crates/stark-engine/src/engine/hybrid/lily_midpoint_tests.rs) · [Full-model parity record](model-experiments/2026-11-17-lily-midpoint-speed-and-release.md)

Add optional readiness metadata for the midpoint restore minimum and the physical chunk interval on the active Lily midpoint path. Derive it from the same rule execution uses. Preserve the meaning of `tail_tokens` and teach the validator to apply the restore rule at the correct position. Document the fields and keep older readiness records readable. [Hybrid restore path](../crates/stark-generate/src/hybrid.rs) · [Prefix validator](../scripts/validate_generation_prefix_cache.py)

**Acceptance.** With the tower loaded, seed a fresh prior snapshot for each case. At position 2,048, suffix length 16 must generate successfully with zero reuse and length 17 must reuse exactly 2,048 tokens. At position 4,096, suffix length two must reuse 4,096 tokens. Compare all outputs with fresh greedy execution in serial and supported MTP modes. Check midpoint-disabled readiness and an image → text transition. The validator’s prediction must agree with worker counters in each case.

## 2. Give each loader an explicit sizing outcome

`ContextSizing::fit_loaded` currently returns `Ok(None)` when the minimum estimate is absent or the limit is below two. Native and hybrid workers can then publish their existing maximum. The audit found no observed finite artifact taking that route. Make this a startup error for a finite loader that promises shared sizing. Use one policy value through load and readiness so a newly added backend has to choose explicitly. [Shared fit and existing missing-estimate test](../crates/stark-engine/src/engine/context.rs) · [Native loader](../crates/stark-generate/src/native.rs) · [Hybrid loader](../crates/stark-engine/src/engine/hybrid/mod.rs) · [Worker dispatch](../crates/stark-generate/src/protocol.rs)

| Loaded case | Required behavior and test |
| --- | --- |
| Finite shared sizing | Converted native text and vision, ordinary hybrid variants, Inkling and Hy4 return the selected window and sizing evidence. Test actual loader wiring or its load-result constructor, including the feature-gated builds. A valid estimate that exceeds budget retains `resource_budget_exceeded`. |
| Undeclared capacity | LLaMBA keeps per-request planning. Worker readiness identifies the undeclared policy and retains the `u32::MAX` wire sentinel. Desktop publishes `context_length: null` and `context_capacity_known: false` under its default configuration. |
| Backend-fixed capacity | The optional GLM EXL3 bridge admits `min(checkpoint, 32,768)` during load. Readiness identifies bridge-managed admission and the admitted cap. Exercise the feature-enabled path and the existing feature-disabled refusal. |

Report an independent bound and its source where the allocator enforces one, such as a Metal buffer or index limit. Represent the absence of an independently measured bound explicitly. Preserve existing numeric fields for older clients. Include Hy4’s optional user cap in the explanation when it binds. Test a checkpoint-bound, a proven backend-bound and a memory-bound fixture, plus an explicit cap.
