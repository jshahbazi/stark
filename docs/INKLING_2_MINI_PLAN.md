# Inkling 2 Mini on Stark

Target the official fixed-three-pass release for native generation on Apple Silicon. The first M5 Max milestone passed all 26 original-weight NVFP4 projection cases after moving the activation outer scale after the dot product. A connected, routed sublayer also passed. The original-checkpoint catalogue entry retains the image tower and separate DSpark weights. [M5 Max reference rates, budget and decision](benchmarks/2026-11-20-inkling-mini-m5-max.md)

The native slice passes short and 4K connected parity. One BF16 word in the attention gate of physical layer 11 caused the last short mismatch. Matching the released runtime's wide GEMV gave bit-exact expert outputs and kept the measured 44-visit budget within the paired no-regression bound. [Short-prefix projection and paired timing](benchmarks/2026-11-21-inkling-mini-short-projection.md)

The native worker uses the 48-visit target with per-visit state, original packed expert banks and a 200,058-token readout. On M5 Max, text prompts of at least 512 tokens at contexts up to 4,352 use 2,048-row source-aligned bulk prefill with drafting off. On a 4,096-token prompt the worker processes 2,048 and 2,044 packed rows, then three width-stable rows in one command and the final seed. Vision, draft-enabled requests, short text, and larger contexts use the existing native path. The source prefill can fall back at load if the old workspace fits the memory budget or source setup fails. ## Implementation order and decisions

### 1. Establish the local baseline and test the expensive operations

The [first milestone study](benchmarks/2026-11-20-inkling-mini-m5-max.md) records the two reference servers and the real-weight components. Its isolated kernel and connected expert tests use Metal and MLX outside the Stark worker. Carry the teacher-forced visit, vision-embedding and full-token fixtures forward into the native implementation.

- **Reference and workload.** On the M5 Max with 128 GiB, freeze the build, hashes, activation and accumulation policy, sampler, stop behavior, and exact rendered token counts. Capture private reference fixtures for representative routed projections, logical-visit boundaries, final logits, and image embeddings. Start with an image-loaded, draft-off reference at 512 and 4,096 input tokens, 256 output tokens, greedy and seeded sampling. Measure cache-cold prefill with resident weights, warm decode and process-start-to-ready separately. Establish reference repeatability and tolerances for component errors, router selections and whole-model logits before inspecting native results. Use the same valid vocabulary, reasoning effort and template in both engines. [Chat template](https://huggingface.co/thinkingmachines/Inkling-2-Mini/blob/6e7c8248f75265bdd4fbab5273304243b5d8c2cb/chat_template.jinja)
- **Native vertical slice.** Exercise packed gate/up and down for an actual NVFP4 core layer and an MXFP8 epilogue layer, including activation scaling and selected-expert reduction. Cover one local visit, one global visit and one cross-pass read. Measure singleton decode and a prefill tile with multiple real routing fixtures from different loop passes. Vary expert overlap across rows and rotate working sets to expose cache-residency effects. Report the spread. Keep routing, activations and selection on GPU. Reuse Stark's command encoding, counters and grouped-expert scheduling where the layouts and math match. Inspect the pinned Apple kernels and preserve licenses and provenance for any port. [Stark command counters](../crates/stark-engine/src/engine/hybrid/decode_graph_counters.rs) · [Grouped expert prefill](../crates/stark-engine/src/engine/hybrid/grouped_expert_prefill.metal) · [Apple packed matvec](https://github.com/ollama/ollama/blob/6949a42ad24450cf567d7ce1ff7d278ebb3eb5d8/mlx/nvfp4_matvec.go)

**Decision.** Keep the source-order mix, RMS, controller, attention and attention-gate projection reductions in the serial path. The complete target's first seeded-cache 4K control took 28.01 ms per step, including F32 vocabulary readback. Validate full-target logits and useful worker throughput on live prefilled requests. The 4K prefill rate has a separate gate. [Pinned oracle attempt](benchmarks/2026-11-21-inkling-mini-pinned-oracle.md) · [Short-prefix parity](benchmarks/2026-11-21-inkling-mini-short-projection.md)

### 2. Bring up the serial worker in its intended performance shape

Add an explicit `inkling2_loop` admission and generation path using the existing native worker lifecycle. Alias immutable weights by physical layer and index mutable state by logical visit. Preallocate scratch, keep a whole serial token on GPU with one submission and one completion, and count waits, uploads and readback bytes from the first run. Keep the expert banks packed and batch the eight selected experts. Separate singleton decode from grouped/chunked prefill. For learned relative attention, tile or fuse the bias calculation so a long prompt cannot allocate a full query-by-key bias matrix. Time the actual greedy and sampled readout over the 200,058 usable vocabulary entries. [Hybrid generation worker](../crates/stark-generate/src/hybrid.rs) · [Stark sampler](../crates/stark-generate/src/hybrid_nucleus.rs) · [Apple tiled prefill](https://github.com/ollama/ollama/blob/6949a42ad24450cf567d7ce1ff7d278ebb3eb5d8/mlx/relative_attention_prefill.go)

Validate the prelude, all three passes, the epilogue and final logits on multi-token prefill and incremental decode. Include 1,023/1,024/1,025 tokens for local ring wrap, and cross the 8,192 global log-scaling threshold. Compare logits on identical teacher-forced prefixes, check greedy agreement, and locate the first divergent visit. Equal seeds across engines establish a token-by-token control only if RNG and sampler also match. For fixed-work sampled timing, replay the same realized prefixes if needed. Qualify normal sampling with distribution checks and seeded replay within each implementation. Profile ordinary prefill and one serial step separately, with stages for experts, attention/convolutions, block residuals and gates, output head, sampling and host waits. Publish throughput from a separate uninstrumented build or run.

**First performance target.** At 4,096 input tokens on this Mac, reach at least 90% of the matched Apple reference's serial useful decode rate and 90% of its cache-cold prefill rate, independently for greedy and sampled requests. The milestone report fixes the rates and their timing boundaries. If a cell misses, take the two largest stages, identify their limits, and estimate the recoverable whole-request gain. Resolve the serial budget before tuning speculation. [Measured targets](benchmarks/2026-11-20-inkling-mini-m5-max.md) · [Performance playbook](PERFORMANCE_PLAYBOOK.md)

The first worker screening cleared both decode ceilings. The M5 Max prefill path groups routes in GPU memory and shares each exact BF16 projection load across four rows. The eight paired connected tests preserve target state, draft taps and continuation logits, with a 0.294 median paired tile-time ratio. Actual full-target 4K prefill took 33.02 seconds. The remaining gap calls for measurement of tiled relative attention and larger shared dense products on the same graph. The whole-model Ollama comparison with the publisher's batched prefill schedule still differs materially. [Full-target and scheduling checks](model-experiments/2026-11-21-inkling-mini-full-target.md) · [Worker screening](model-experiments/2026-11-21-inkling-mini-worker.md)

The 512-row trace isolated the first packed dense, attention and expert mismatches. Matching the original arithmetic, then testing the stock scheduler’s bulk widths and seed, reproduced every BF16 visit residual and all four F32 logit vectors on four held-out 4K inputs. Prefix retention for this worker mode uses complete 2,048-token bulk chunks and verifies that the following prompt still reaches the same boundary. [Packed prefill and parity](model-experiments/2026-11-21-inkling-mini-packed-prefill.md) · [Early stage profile](model-experiments/2026-11-21-inkling-mini-prefill-profile.md)

### 3. Qualify vision, prefix reuse and memory alongside the target

- **Vision.** Start processor and tower work from the reference fixtures while the target graph is being built. Verify patch/grid order, temporal packing, normalization, projector output, placeholder expansion and image-conditioned logits, then run real image-answer controls. Compare identical text requests on diagnostic text-only and default image-loaded workers. For cold and reused text, predeclare the allowed regression from repeated baseline variability and require both cells to pass. [Vision primitives](../crates/stark-engine/src/engine/vision/tower.rs) · [Image qualification](IMAGE_DEFAULT_PARITY_PLAN.md)
- **State.** Restore global KV lengths, local ring contents and write positions, and all four convolution histories per logical visit at a complete prefill boundary. Keep per-token cross-pass scratch ephemeral and explicitly inventory draft taps, draft KV, committed position and any persistent feature state once DSpark is active. Reuse the immediately preceding scoped request under matching model instance, context and draft options. Capture inside the efficient prefill path and replay the suffix at the same chunk geometry as fresh execution. The Apple reference explicitly aligns prefill to snapshots because batch shape can change low-precision expert selection. Measure follow-up time to first token and reused token count. Compare reuse on, reuse off and fresh execution for growing, shrinking, divergent and chunk-edge inputs, with exact output hashes and expected reused counts. Cover cancellation, error, reset, scope change and restart. [Apple cache and prefill implementation](https://github.com/ollama/ollama/blob/6949a42ad24450cf567d7ce1ff7d278ebb3eb5d8/mlxrunner/model/inkling2/model.go#L133-L153) · [Ring snapshots](../crates/stark-engine/src/encodable_block/mixer/attention/state.rs) · [Worker prefix contract](MODEL_ONBOARDING.md)
- **Memory.** With two-byte KV, each global position costs `8 visits × 2 × 8 heads × 128 × 2 bytes = 32 KiB`. The 40 full local rings total 160 MiB. That gives roughly 1.16 GiB of target KV at 32,768 positions and 32.16 GiB at the upstream 1,048,576 limit. Charge weights, images, draft state, verification and prefill scratch, snapshots, staging, allocator headroom and in-flight copies separately. Verify estimates against observed peak and admission failures. Expand context after the 4K and 32K runs establish cost and correctness.

### 4. Qualify DSpark, then choose a default

Implement target-tap capture, the block drafter, and batched verification against serial target rows. Start with one proposal. Exercise every accepted prefix length, wrong first/last proposal, full acceptance, EOS, and cancellation. Gate on real-model target rows, rollback state and the next committed step. Verify greedy equality, the sampled target distribution under the chosen acceptance rule, and reproducibility of seeded runs within that rule. The existing DFlash and exact sampling paths provide building blocks. DSpark needs its own Markov head, tap indexing and cache semantics. [Stark DFlash block](../crates/stark-engine/src/encodable_block/dflash.rs) · [Generation worker](../crates/stark-generate/src/hybrid.rs)

Measure committed tokens per round divided by draft, verify, finish and host time. Measure marginal verify-row cost, acceptance by position and peak memory across short depths, extending toward seven proposals only while the cost model supports it. Remove host round trips before optimizing individual row kernels. Compare draft-off, winning fixed depth and any proposed adaptive policy on prose, code and natural multi-turn or tool use, greedy and sampled. Derive costs on Inkling. With the tower loaded, exercise text with draft and cache → image with zero proposals/reuse → fresh text with the selected draft policy → a reusable follow-up. Keep serial selectable and publish the default supported by the measurements. [New-family checklist](PERFORMANCE_PLAYBOOK.md#checklist-for-a-new-family)

## Benchmark and release criteria

- Compare identical artifacts, effective precision, input tokens, seeds, stop/output budgets, cache state and request cadence. Record process-start-to-ready, time to first token after idle and on cold/warm prompts, prefill tok/s, useful decode `(sampled tokens − 1) / decode seconds`, request time, reused tokens, draft counters and peak memory. Separate fixed-work timing from natural completions. Keep raw inputs, outputs, token IDs and model values private. Publish aggregate errors, times, counts and hashes.
- For speed decisions use alternating arms in one loaded Stark worker, or bracket separate engines/builds in both launch orders. Record median *paired* ratios and spread, an unaffected control and host eligibility. Freeze minimum samples and gates before the run. For an optimization default, start with eight valid pairs per decision cell, at least seven wins, a gain above the larger of 10% and baseline variability, and no primary cell more than 5% slower. Check held-out inputs. For the cross-engine 90% target use the paired rate ratio and report noise that could change the decision. [Measurement rules](PERFORMANCE_PLAYBOOK.md#measuring)
- Admit the pinned pack through normal preparation and `stark-generate`. Verify readiness, chat/streaming/stop behavior, images, memory refusal, cancellation and recovery. Gate function tools on template-bound rendering, parsing, tool-result round trips and malformed output. Inkling emits a named `<|content_invoke_tool_json|>` envelope. Test the actual API before advertising it. Check useful responses on held-out chat, code, image and tool tasks alongside numerical agreement. [Tool qualification](MODEL_ONBOARDING.md#assess-and-qualify-function-tools)
- Open an [experiment record](model-experiments/TEMPLATE.md) before the first run. Record failed, invalid, deferred and inconclusive attempts. Update the [playbook](PERFORMANCE_PLAYBOOK.md) in the same change when an experiment changes a lever, gate or open idea. Record numerical qualification, measured speed, release and installed verification separately. The first deliverable is the baseline and real-weight slice, followed by a decision on the full port.
